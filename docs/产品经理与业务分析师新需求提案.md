## 1. 概述

本文档基于 v1.2.0 技术优化完成后的产品现状，提出 v1.3.0 及后续版本的新功能需求。
每项需求均从产品价值和业务合理性两个维度进行分析评估。

---

## 2. 新需求提案

### 2.1 纪念日提醒通知

**需求描述**：在纪念日前一天和当天，通过浏览器通知提醒用户。

**用户故事**：作为妻子，我希望在纪念日到来前收到提醒，不错过重要日子。

**产品价值**：
- 增强产品的情感连接属性
- 提升日活和用户回访率
- 差异化竞争力（同类产品少有提醒功能）

**业务分析**：
- 技术可行性：高（使用 Notification API + Service Worker）
- 开发成本：约 2 人天
- 风险：iOS Safari 对 Notification API 支持有限，需降级方案
- 优先级：P1（高价值、低成本）

**合理性评估**：★★★★★ 强烈建议。纪念日是产品核心定位，提醒功能是自然延伸。

---

### 2.2 自定义情话库

**需求描述**：允许用户自行添加、编辑、删除情话，与系统情话混合展示。

**用户故事**：作为丈夫，我希望添加属于我们两人的专属回忆和话语，让产品更有专属感。

**产品价值**：
- 深度个性化，增强用户粘性
- 用户生成内容（UGC）提升产品温度
- 差异化核心优势

**业务分析**：
- 技术可行性：高（localStorage 存储，无需后端）
- 开发成本：约 3 人天（含 UI + 数据管理 + 与现有系统融合）
- 风险：存储空间限制（localStorage 5MB），需做容量提示
- 优先级：P1（高价值、中成本）

**合理性评估**：★★★★★ 强烈建议。个性化是情感类产品的核心诉求。

---

### 2.3 纪念日相册

**需求描述**：在首页添加照片墙/相册功能，展示两人的合照或重要时刻。

**用户故事**：作为妻子，我希望在纪念日页面看到我们的照片，回顾美好时光。

**产品价值**：
- 视觉化情感表达，冲击力强于纯文字
- 提升首页内容丰富度
- 增强产品"仪式感"

**业务分析**：
- 技术可行性：中（照片需存储在本地/图床，纯前端方案受限）
- 开发成本：约 5 人天（含图片上传/管理/展示/轮播）
- 风险：图片存储方案选择（localStorage 容量不足，需引入 IndexedDB 或图床方案）
- 优先级：P2（高价值、高成本）

**合理性评估**：★★★★☆ 建议但需分期。v1.3.0 可先做静态照片轮播（预设照片），v1.4.0 再做自定义上传。

---

### 2.4 纪念日倒计时动画

**需求描述**：在纪念日当天展示特殊的庆祝动画（烟花、祝福语弹出等）。

**用户故事**：作为妻子，在纪念日打开应用时看到惊喜动画，感受到用心和浪漫。

**产品价值**：
- 峰值体验，创造"惊喜时刻"
- 增强产品传播性（用户更愿意截图分享）
- 提升情感共鸣

**业务分析**：
- 技术可行性：高（CSS 动画 + Canvas 粒子效果）
- 开发成本：约 2 人天
- 风险：动画性能需优化（低端机兼容）
- 优先级：P2（中价值、低成本）

**合理性评估**：★★★★☆ 建议。低成本高回报的惊喜功能。

---

### 2.5 恋爱日记/时间线

**需求描述**：以时间线形式记录恋爱中的重要事件（第一次约会、第一次旅行等）。

**用户故事**：作为丈夫/妻子，希望记录恋爱中的点点滴滴，形成专属的恋爱时间线。

**产品价值**：
- 深度产品化，从"工具"升级为"回忆录"
- 提升用户生命周期价值
- 创造差异化

**业务分析**：
- 技术可行性：中（需设计时间线 UI + 数据模型 + 编辑功能）
- 开发成本：约 5 人天
- 风险：数据持久化（localStorage 限制），数据量大后性能问题
- 优先级：P3（中价值、高成本）

**合理性评估**：★★★☆☆ 长期规划。建议先验证相册功能后再考虑。

---

### 2.6 心情打卡

**需求描述**：每天记录心情状态（开心/甜蜜/想念等），形成心情日历。

**用户故事**：作为妻子，我希望记录每天的心情，看到一段时间内的情绪变化。

**产品价值**：
- 增加日活触点
- 数据可视化增强粘性
- 情感数据可形成专属报告

**业务分析**：
- 技术可行性：高（localStorage + 日历 UI）
- 开发成本：约 3 人天
- 风险：用户坚持度低，需要提醒机制配合
- 优先级：P3（中价值、中成本）

**合理性评估**：★★★☆☆ 可选。需配合 2.1 提醒功能才有更好的使用率。

---

### 2.7 多语言支持

**需求描述**：支持英文/日文/韩文等语言切换，方便跨国恋用户。

**用户故事**：作为跨国恋情的用户，希望用双方都能理解的语言使用产品。

**产品价值**：
- 拓展用户群体
- 国际化基础建设

**业务分析**：
- 技术可行性：中（Vue I18n 插件 + 翻译文件）
- 开发成本：约 3 人天（含翻译 + 文案管理）
- 风险：情话翻译质量（文化差异导致语义流失）
- 优先级：P4（低价值——当前用户定位为中文用户）

**合理性评估**：★★☆☆☆ 暂不建议。当前产品定位明确（中文用户），过早国际化分散精力。

---

### 2.8 分享卡片生成

**需求描述**：将纪念日倒计时或情话生成精美的分享图片，便于转发到微信朋友圈。

**用户故事**：作为妻子，希望将甜蜜的纪念日或情话分享给朋友。

**产品价值**：
- 社交传播，免费获客
- 满足用户炫耀/分享心理
- 提升品牌曝光

**业务分析**：
- 技术可行性：中（Canvas 截图 + html2canvas 或纯前端生成）
- 开发成本：约 4 人天（含卡片设计 + 生成逻辑 + 下载/分享）
- 风险：微信内嵌浏览器兼容性
- 优先级：P1（高价值、中成本）

**合理性评估**：★★★★★ 强烈建议。分享是产品增长的核心引擎。
